# JA Capital

Четыре AI-агента торгуют криптой на **реальных котировках**:

- **Рустам** следит за трендами шести монет и читает новости CoinDesk, The Block, Decrypt и Cointelegraph;
- **Джама** оценивает риск каждой идеи, считает стоп, тейк и размер позиции;
- **Нод** превращает сводку и риск в сигнал с уверенностью в процентах;
- **Артур** открывает и закрывает сделки, переносит стоп в безубыток, соблюдает дневной лимит убытка.

Агенты работают на сервере круглосуточно, даже когда страница закрыта. Браузер показывает 3D-офис с персонажами, ленту переговоров, портфель и графики.

Интерфейс в стиле Apple со стеклянными панелями, две темы: светлая — в офисе день, тёмная — ночь, «Авто» — как в системе. Сцену можно поворачивать мышью, двойной клик возвращает вид. Без WebGL или с `?2d` в адресе включается прежняя 2D-сцена.

## Счета

Счёт выбирается в шапке интерфейса, выбор запоминается на сервере.

| Счёт | Что происходит | Что нужно |
|---|---|---|
| **Виртуальный счёт** | Ненастоящие деньги ($10 000), реальные котировки и новости. Есть всегда. | Ничего, кроме пароля |
| **Binance — реальный счёт** (`BINANCE_ENV=live`) | Ордера уходят на ваш настоящий счёт Binance (фьючерсы USDT-M или спот). | Ключ API Binance |
| **Binance — демо-счёт** (`BINANCE_ENV=demo`) | Ордера уходят на демо-торговлю Binance по реальным ценам. | Ключ API из режима демо-торговли |

Агенты и лента общие, а деньги, позиции, история сделок, автосделки и пауза у каждого счёта свои. Если переключиться, позиции на прежнем счёте не бросаются: стопы, тейки, перенос в безубыток и выход по времени по ним продолжают работать, новые сделки открываются только на выбранном счёте.

### Реальный счёт Binance: защита

- Переключение на реальный счёт требует подтверждения в интерфейсе. В первый раз включён ручной режим: Артур ждёт вашего «да» по каждой сделке.
- Белый список IP у ключа и Render: Render выходит в интернет с меняющихся адресов из общих диапазонов, а Binance принимает в белый список только отдельные IP. Поэтому либо ключ без списка IP, либо прокси со статическим IP (QuotaGuard, Fixie и т. п.) в `BINANCE_PROXY` — тогда в белый список добавляются IP прокси (их видно в логе при запуске).
- Один ордер — не больше `BINANCE_MAX_ORDER_USD` (по умолчанию 200 USDT). Плечо — `LEVERAGE` (по умолчанию 1×), маржа — изолированная.
- При подключении сервер проверяет ключ: если у него включён **вывод средств**, счёт не подключится. Для фьючерсов у ключа должно быть право «Enable Futures».
- Стопы и тейки ведёт сервер. Дополнительно на бирже ставится **страховочный стоп** чуть дальше основного — он сработает, если сервер выключится или пропадёт связь.
- Каждые 5 минут позиции сверяются с биржей; дневной лимит убытка останавливает новые сделки до следующего дня.
- Шапка подсвечивается красным, пока выбран реальный счёт.

### Ключ API Binance

1. Binance → профиль → **Управление API** → создать ключ (системный, HMAC).
2. Права: **чтение**, **спотовая торговля** или **фьючерсы** (для `MARKET_TYPE=swap` — «Enable Futures»). Вывод средств **не включайте**.
3. Лучше ограничить ключ IP-адресами сервера: в Render они видны в настройках сервиса (раздел исходящих адресов).
4. Если в Binance включён режим хеджирования позиций, офис это учтёт сам.

Задайте в панели хостинга `BINANCE_API_KEY`, `BINANCE_API_SECRET` и `BINANCE_ENV=live` (или `demo`). Котировки по умолчанию берутся с Binance (`QUOTES=binance`).

Старая настройка `TRADING_MODE=exchange` + `EXCHANGE=bybit` + `EXCHANGE_API_KEY` по-прежнему работает: демо-счёт или тестовая сеть Bybit появятся в списке счетов.

## Запуск на своём компьютере

Нужен Node.js 18.17 или новее.

```bash
npm install
cp .env.example .env      # задайте ACCESS_PASSWORD и, если нужно, ключи
npm start
```

Откройте http://localhost:3000 и введите пароль.

Проверка без интернета и ключей, на имитации биржи (пароль `demo`, в списке будет «Binance — имитация»):

```bash
npm run mock
```

## Запуск на Render

1. Загрузите папку в репозиторий GitHub.
2. В Render: **New → Blueprint**, выберите репозиторий. Настройки возьмутся из `render.yaml`.
3. Задайте секреты: `ACCESS_PASSWORD`, при необходимости `BINANCE_API_KEY`, `BINANCE_API_SECRET` и `ANTHROPIC_API_KEY`.

Важно:

- **Регион** — Франкфурт (уже указан в `render.yaml`). Биржи блокируют запросы с американских серверов (ошибка 451).
- **Бесплатный план засыпает** через 15 минут без посетителей, и агенты перестают торговать. Для круглосуточной работы нужен платный план (в `render.yaml` указан `starter`) с диском для сохранения состояния.

### Вид за окнами

Положите в `public/models/env/` две панорамы с одним и тем же кадром: `nyc_day.jpg` (день) и `nyc_night.jpg` (ночь), соотношение сторон около 3:1. Светлая тема покажет дневную, тёмная — ночную; каждое окно показывает свою часть панорамы. Без этих файлов за окнами нарисованный город.

## Структура

- `server.js` — веб-сервер, вход по паролю, WebSocket, расписание опросов.
- `src/` — котировки (`market.js`), новости (`news.js`), логика агентов (`brain.js`), исполнение ордеров (`broker.js`), офис и сделки (`office.js`), Claude (`claude.js`).
- `client/` — исходники интерфейса: стили `app.css`, тема `theme.js`, 3D-офис `scene3d.js` (Three.js), 2D-запасная сцена `scene.js`. После правок соберите `public/index.html` командой `python3 build.py`.
- `public/vendor/` — Three.js r169 (лицензия MIT, `three-LICENSE.txt`), `public/models/` — модели персонажей, `public/models/props/` — мебель: glTF с буфером в base64 внутри `.json` и текстуры `.jpg`. Скелет персонажей для сидения, ходьбы и печати строится в браузере по пропорциям модели. Если модель не загрузится, на её месте остаётся простая фигура или мебель.

## Claude

Если задан `ANTHROPIC_API_KEY` (ключ Claude API с console.anthropic.com, оплачивается отдельно от подписки Claude):

- Рустам разбирает заголовки новостей через Claude: какие монеты затронуты, какой тон, насколько это важно, перевод на русский;
- работает **планёрка** и **разговор с любым агентом**.

Без ключа новости разбираются словарём, а планёрка и разговор выключены. Число обращений к Claude ограничено: 40 разговоров, 8 планёрок и 30 разборов новостей в час.

## Как устроена торговля

- Котировки обновляются каждые `TICKER_SECONDS`, свечи — `TIMEFRAME` (по умолчанию 5 минут).
- Сводка Рустама — каждые `SCAN_SECONDS` и сразу после важной новости.
- Джама рискует `riskPct`% капитала на сделку; один ордер не больше `MAX_ORDER_USD` (виртуальный счёт) или `BINANCE_MAX_ORDER_USD` (Binance).
- **Стопы и тейки ведёт сервер** и закрывает позицию рыночным ордером. На фьючерсах Binance дополнительно стоит страховочный стоп на бирже; на других биржах при выключенном сервере позиции ничем не защищены.
- Каждые 5 минут Артур сверяет фьючерсные позиции с биржей. Позицию, которую закрыли вручную на бирже, он убирает из учёта. Позицию, открытую на бирже без него (например, после перезапуска с чистым диском), берёт под контроль со своим стопом и тейком.
- Профиль риска, порог сигналов, лимиты, ручное подтверждение сделок и паузу торговли можно менять прямо в интерфейсе.
